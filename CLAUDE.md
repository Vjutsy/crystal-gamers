# Crystal Gamers — інструкції для AI-асистентів

Кооперативний 2.5D-екшен у браузері на 1–4 гравців. Від Sonic 3D Blast беремо геймплей і камеру, **не візуал**.
Темне фентезі з коміксним лайн-артом, low-poly 3D, фіксована ізометрична камера (своя в кожного гравця).

Автор програмує трохи: пояснюй рішення простою мовою в описі PR. Спілкування — українською, код і коментарі в коді — англійською.

## Арт-стиль (рішення автора, 2026-11-24)

- **Настрій:** «тривожна казка» — моторошно, але тепло; для всіх віків.
- **Основа:** кельтські орнаменти, середньовічні гобелени, акварельні/пастельні текстури, наївне мистецтво. Головний референс стилю — мультфільми Cartoon Saloon («Таємниця Келлс», «Пісня моря», «Вовкоходи»).
- **Палітра:** приглушена, землиста, трохи «припилена»; яскраві акценти лише два — бірюзовий кристал і теплий вогонь.
- **Техніка в Babylon.js** (Фаза 6): контур (inverted hull + screen-space по глибині/нормалях, з легким «тремтінням» лінії), toon-шейдер на NodeMaterial з 2–3 плямами світла, текстура паперу в шейдері й постобробці (зерно, віньєтка), 2D-картки для трави, листя й далекого плану, асиметричні моделі з вмальованими орнаментами, градієнтне й локальне світло замість PBR.
- Grease Pencil / Freestyle із Blender у гру не переносяться — їх замінюють контур у шейдері та штрихи в текстурах.
- Кожна локація — свій час доби (освітлення).
- Поки йде робота над механіками, сцена лишається сірою заготовкою з примітивів: стиль не впроваджуємо раніше Фази 6 без окремого рішення.

## Стек

- `apps/client` — Vite + TypeScript + Babylon.js 9. Тільки рендер, ввід, UI, передбачення свого героя, інтерполяція чужих.
- `apps/server` — Node.js + Colyseus 0.18. Авторитетний сервер: кімнати, симуляція, вороги, адаптація рівня.
- `packages/shared` — код, який виконується І на клієнті, І на сервері: крок симуляції, константи, дані героїв, формат рівня.

## Архітектурні правила (не порушувати без нового ADR)

1. **Сервер — єдине джерело правди.** Клієнт надсилає лише ввід (намір), ніколи — позиції чи результати.
2. **Уся ігрова логіка — у `packages/shared`.** `shared` не імпортує Babylon, DOM, Colyseus чи Node API.
3. **Детермінізм симуляції:** фіксований крок (`SIM_DT`), жодних `Math.random()`, `Date.now()`, `performance.now()` у `shared` — тільки `createRng(seed)` із `shared`.
4. **Числа балансу — дані, не код.** Параметри руху й бою живуть у конфігах у `shared` (`tuning`), щоб їх тюнити без переписування логіки.
5. Клієнт не робить припущень про інших гравців — лише інтерполює стан із сервера.
6. Нова залежність — тільки з причиною в описі PR; версії фіксуються точно (без `^`).
7. **Рівні вирівняні по екрану** (рішення автора): головні маршрути йдуть уздовж осей екрана, щоб рухатись переважно однією клавішею. Рівень описується в екранних координатах (+Z = вгору екрана / W, +X = вправо / D) і проходить через `orientLevel()` (поворот на 45°).

## Команди

- `pnpm install` — залежності
- `pnpm dev` — клієнт (http://localhost:5173) + сервер (ws://localhost:2567) разом
- `pnpm check` — lint + typecheck + тести (запускай перед кожним комітом)
- `pnpm test` — Vitest; `pnpm format` — автоформат Biome
- `pnpm build` — збірка всіх пакетів

## Як працюємо

1. **Spec:** нова фіча починається зі сторінки в `docs/specs/NNNN-name.md` (шаблон `docs/specs/_template.md`) із критеріями «готово».
2. **План:** перед кодом — короткий план кроків, автор погоджує.
3. **Тести спершу** для логіки в `shared`.
4. **Маленькі PR:** одна фіча — одна гілка (`feat/…`, `fix/…`) — один PR. Коміти в стилі Conventional Commits.
5. **Плейтест:** «відчуття» перевіряє автор у браузері. Після змін у русі/бою напиши, що саме варто відчути й перевірити.
6. **Рішення** фіксуються в `docs/adr/NNNN-name.md`. Не переписуй прийняті ADR — створюй новий, що їх замінює.

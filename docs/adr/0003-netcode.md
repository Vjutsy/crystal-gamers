# ADR-0003: Мережева модель — авторитетний сервер, передбачення свого героя, інтерполяція чужих

- Статус: прийнято (2026-11-25)
- Дата: 2026-11-25

## Контекст

- Кооператив до 4 гравців у браузері, WebSocket (TCP) через Colyseus.
- Рух швидкий (до ~23 м/с у спін-деші), керування має бути миттєвим.
- Уся симуляція вже детермінована й спільна (`stepGame`, ADR-0002), тож клієнт може точно повторити розрахунок сервера.
- Гравці не б'ються між собою (PvE), тож рідкісні розбіжності не критичні для чесності.

## Варіанти

1. **Тільки сервер, клієнт показує знімки.** Найпростіше, але керування запізнюється на весь пінг (100–200 мс) — для платформера неприйнятно.
2. **Lockstep** (усі клієнти рахують однаково, обмінюються лише вводом). Мінімальний трафік, але один повільний гравець гальмує всіх, а вхід посеред гри складний.
3. **Авторитетний сервер + передбачення свого героя + інтерполяція чужих** (класика швидких мережевих ігор).

## Рішення

Варіант 3.

- Клієнт кожен тік надсилає `{seq, input}`; сервер застосовує ввід кожного гравця у своєму тіку 60 Гц і зберігає `lastSeq` — номер останнього обробленого вводу.
- Сервер розсилає знімок стану 20 разів на секунду (Colyseus schema patches).
- **Свій герой:** клієнт одразу застосовує ввід локально (передбачення) і зберігає історію. Отримавши знімок, бере стан свого героя із сервера, відкидає підтверджені вводи (`seq ≤ lastSeq`) і заново проганяє непідтверджені. Якщо результат відрізняється від показаного, показ плавно (за ~100 мс) підтягується, а не стрибає.
- **Чужі герої:** показуються з буфера знімків із затримкою ~100 мс з лінійною інтерполяцією між двома знімками.
- **Події світу** (кристали, удари, чекпоінти, підняття) вирішує лише сервер. Клієнт може показати миттєвий ефект для свого героя (наприклад, зникнення кристала), але правда — у знімку.

## Наслідки

- Клієнт має вміти «перемотати» свого героя: стан руху — звичайні дані (`MoverState`), фізичний світ статичний, тож повтор 6–12 тіків коштує ~2–3 мс.
- Трафік: ~4 героїв × ~60 байт × 20/с — дрібниця навіть для мобільного інтернету.
- Рухомі об'єкти рівня (майбутні платформи, вороги) теж мають бути детерміновані від номера тіку, інакше передбачення героя на них розходитиметься.
- Через TCP втрата пакета дає затримку, а не втрату; інтерполяційний буфер ~100 мс це ховає.
